# Freight Rate Prediction Challenge

Private repository: [vothai17072002/freight-rate-ml-assessment-2026-10-05](https://github.com/vothai17072002/freight-rate-ml-assessment-2026-10-05).
Grant the reviewer access before submitting this private URL.

This solution predicts `posted_rate` for the 12,000 supplied November-December
2025 loads. It contains a read-only input audit, a reproducible temporal
development protocol, two fitted CatBoost models, final prediction files, and a
six-page PDF with the December chart generated by the original scorer.

The main model uses shipment, location, calendar and market features. The
December model uses the six available inputs: `pickup`, `delivery`, `distance`,
`equipment`, `weight` and `date`. Both exclude `quote_signal` and fit
`log(posted_rate / distance)`; inference exponentiates the prediction and
multiplies it by the supplied distance.

## Recorded results

Model configuration and feature policies were selected using **January-June
training and July-August selection**. The selected configurations were frozen
before the **September-October holdout**, then refitted on all January-October
labeled data for the final submission.

The primary model improves holdout RMSE by 4.9% versus the baseline. The primary
and reduced policies are selected separately to respect their input contracts;
the September-October result is not used to switch policies afterward.

A separate **post-selection cold-city stress** removes eight deterministically
chosen cities from January-June training, fits the already selected primary
configuration on 22,894 remaining rows, and evaluates 2,004 July-August loads
touching those excluded cities. RMSE is $540.54, MAE is $141.82 and WAPE is 7.04%.
These are controlled development results, not the actual November-December
unseen-city score. See `reports/cold_city_stress.json` for the exact rule and
cities.

**The organizer's final validation score is unknown.** `validation.csv` has no
target labels. The supplied `score.py` checks submission structure and produces
the chart; it does not measure prediction accuracy.

## Setup and full reproduction

The recorded environment is CPython 3.13 on Windows. Exact tested package
versions are pinned in `requirements.txt`; source hashes, model hashes, random
seed and versions are also recorded in `artifacts/metrics.json`.

From the project root in PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m src.run_all
```

The default workflow audits the original input copies, reads the recorded
July-August candidate comparison, selects the eligible configurations, evaluates
the chronological holdout, refits final models, writes both output CSVs, runs
the original scorer, and builds the PDF. It verifies that the recorded candidate
results match the development CSV's SHA-256 hash. It does not use final
validation labels.

To independently repeat the bounded candidate comparison as well:

```powershell
.\.venv\Scripts\python.exe -m src.run_all --recompute-selection
```

To regenerate predictions, scorer output and PDF using the supplied fitted
models without retraining:

```powershell
.\.venv\Scripts\python.exe -m src.run_all --skip-training
```

These two options cannot be combined. The recomputed selection run is slower
because it fits all recorded candidates. On other platforms use the equivalent
virtual-environment Python executable; the recorded Windows artifacts and
results remain the reference snapshot.

## Data preparation and feature decisions

- Original inputs under `data/` remain unchanged. Audit files record their
  SHA-256 hashes; IDs are used only to align output with the supplied template.
- Training has 300 missing and 292 nonpositive weights; validation has 165 and
  145 respectively. Treat nonpositive weights as missing, add a quality flag,
  and fit numeric medians only on the training side of each split.
- Training has 374 missing `market_index` values; validation has 249. The primary
  pipeline adds a missingness flag and applies training-only imputation.
- Validation contains eight new cities affecting 1,447 loads, and 1,461 loads
  on unseen directed lanes. Categorical handling supports unseen values; the
  primary model also uses the supplied geography. Coordinate bounds do not
  prove that the locations are geographically correct.
- January-August evidence shows the `quote_signal` association changing sign
  between months and becoming almost zero in August. It is excluded from both
  submission models. Its definition and timing are unknown; instability does
  not establish target leakage. Quote-based models remain diagnostic trials.
- Rare expensive target values are retained. Their magnitude alone does not
  prove data corruption; dollar RMSE is sensitive to them.
- Shipment features include distance transforms and directed lane; calendar
  features include weekdays, date counters, weekend and cyclic terms. The
  primary model additionally uses supplied coordinates, coordinate differences
  and `market_index`. No observed target or ID becomes a predictor.

Both selected CatBoost configurations use 700 iterations, depth 6, learning
rate 0.055, L2 leaf regularization 5, seed 42 and four threads. Selection minimizes
July-August dollar RMSE within each input policy, with MAE as a tie-breaker.
Thirteen recorded trial results are retained. Six configurations implemented in
the shared production pipeline are eligible; the remaining trials are recorded
comparisons. See `src/train.py`, `artifacts/selected_config.json` and
`experiments/results.json` for the exact sets.

The December input omits coordinates, `market_index` and `quote_signal`.
A dedicated reduced model avoids inventing future signals or an external city
lookup. Its 31 predictions describe the fixed scenario under learned calendar
effects, with no observed December rates to validate the curve. A tree model
does not extrapolate a new time trend, and January-October history alone cannot
establish repeated December seasonality.

## Model references

CatBoost accepts categorical columns and derives numerical statistics internally;
the CatBoost branch therefore passes string categories directly, while Ridge
uses its own one-hot preprocessing. See the official
[categorical feature documentation](https://catboost.ai/docs/en/features/categorical-features).
This solution explicitly stores training-only medians and missingness flags,
although CatBoost also offers built-in numerical missing-value handling; see
[missing values processing](https://catboost.ai/docs/en/concepts/algorithm-missing-values-processing).
